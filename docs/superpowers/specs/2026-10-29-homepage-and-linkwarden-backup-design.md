# 首页与 Linkwarden 一键备份设计

## 目标

在浏览器首页增加一键下载备份和从 ZIP 导入恢复，并在从未备份或最近一次成功备份已超过 7 天时显示首页提醒。备份覆盖首页及 Linkwarden 的持久化数据，并提供恢复说明。首页同时提供一个直接打开 Linkwarden 的入口。

## 用户流程

1. 首页通过 `/api/backup/status` 读取最近一次成功备份时间。
2. 如果从未备份或距离最近备份超过 7 天，首页顶部显示提醒和“立即备份”按钮。
3. 用户点击按钮后，前端向同源 `/api/backup` 请求压缩包，并用浏览器下载为带时间戳的 ZIP 文件。
4. 下载成功后刷新备份状态；提醒立即消失，并在备份再次超过 7 天时重新出现。
5. 首页明确说明 ZIP 包含 `.env`、API Token 和数据库凭据，文件本身不加密，提醒用户妥善保管。
6. 首页提供“导入备份”入口。用户选择 ZIP 后，服务端先验证清单、归档路径、格式和大小，并暂存待导入数据；通过验证后先生成并下载当前实例的完整回滚备份。
7. 当前备份完整交付后，页面显示将被替换的数据范围和所选归档生成时间。用户再次确认后，服务端在维护状态下整体替换 Linkwarden 数据库、附件、首页状态和 Obsidian 笔记。
8. 导入成功后退出维护状态，刷新首页及 Linkwarden 同步状态。当前 `docker-compose.yml`、`.env` 和 Token 不自动导入或覆盖；ZIP 中这些文件供异机恢复时手动使用。
9. 首页顶栏增加“打开 Linkwarden”入口，直接导航到 `http://localhost:3010`，使用当前标签页。

## 备份内容

ZIP 中使用稳定的顶层目录，并附带生成时间、项目版本和恢复步骤：

- `linkwarden/database.dump`：通过 `pg_dump` 生成的 PostgreSQL 自定义格式逻辑备份。
- `linkwarden/data/`：Linkwarden 持久化附件目录。
- `homepage/state.db`：使用 SQLite 在线备份接口导出的首页状态数据库，避免直接复制正在写入的数据库文件。
- `homepage/浏览器首页笔记.md`：当前指定的 Obsidian 笔记。
- `homepage/note-conflicts/`：冲突及笔记写入前的保留副本。
- `deployment/docker-compose.yml`、`deployment/.env`、`deployment/homepage-secrets/linkwarden_api_token.txt`：部署配置和恢复所需凭据。敏感值按用户选择原样写入未加密 ZIP。
- `RESTORE.txt` 与 `manifest.json`：数据说明、生成时间和恢复步骤。

导入时只恢复数据库、附件、首页状态、Obsidian 笔记及冲突副本。ZIP 中的 Compose、`.env` 和 Token 文件不自动覆盖本机运行配置。

MeiliSearch 索引不打包；它是可重建的搜索索引。前端构建产物和项目源码不纳入运行数据备份。

## 后端与部署架构

- 首页后端保留现有 app 与 data 网络隔离，不连接 PostgreSQL，也不挂载 Docker socket。
- 新增一个没有宿主机端口的备份服务和两条专用内部网络：`backup_api` 只连接首页后端与备份服务，`backup_db` 只连接备份服务与 PostgreSQL。Linkwarden 不加入这两条网络。
- 备份服务通过 `backup_db` 使用 `.env` 中的 PostgreSQL 凭据执行 `pg_dump`，备份流程只读取 Linkwarden 数据、首页状态、Obsidian 笔记、Compose 文件、`.env` 和 Token 文件。凭据只提供给备份容器，不放入首页后端环境或日志。
- 导入时备份服务另外接收已校验的暂存归档，并在维护窗口内替换数据库及数据文件。它对需要替换的 bind mount 具有写权限；这些挂载只提供给备份服务，备份操作本身不会修改它们。
- 同源 `/api/backup`、`/api/import/prepare`、`/api/import/commit` 路由代理备份服务操作，并设置下载文件名和 `application/zip` 类型；现有 Host/Origin 校验继续保护状态变更请求。
- 首页状态数据库升级到下一个 schema 版本，持久化 `last_backup_at`。只有归档生成并完整交付给前端后，前端确认接收，后端才记为成功。
- 首页后端维护一个导入维护状态；维护期间暂停首页写请求及笔记同步写入，避免与文件替换并发。
- 导入在单独的临时目录展开。服务端校验 manifest、兼容版本、允许的相对路径、解压后总大小、PostgreSQL dump 清单、SQLite `integrity_check` 和必需文件后才允许提交。
- 提交前保留当前数据库和文件副本。数据库先恢复到 staging 数据库，校验通过后再切换；附件、首页状态和笔记替换失败时恢复原数据库及文件。完成或回滚后清理暂存内容并退出维护状态。
- 导入完成后保留本次自动生成的回滚备份时间作为最近备份时间，避免导入旧的 `state.db` 覆盖当前记录。

PostgreSQL dump 本身提供一致的事务快照。附件目录在相邻时间复制；备份期间若有新附件写入，归档可能包含数据库快照之后创建的孤立附件，但数据库仍以 dump 为准。恢复说明会说明这一点。

## 前端行为

- 在首页搜索和书签内容之前显示可访问的提醒条，支持从未备份、刚好 7 天内、超过 7 天、正在备份、成功和失败状态。
- 按本地时区显示最近备份时间；7 天边界使用精确时间差计算。
- 备份进行时禁用重复点击并显示进度状态；失败时保留提醒并显示可读错误。
- 归档经服务端流式传输给浏览器，不在前端内存中缓冲整个 ZIP。服务端确认响应流完整结束后记录最近成功时间；若传输中断则不更新。
- 导入 ZIP 通过流式上传进入服务端临时目录，前端不把大文件读入内存。准备、回滚备份下载和导入提交状态通过状态接口轮询。

## 错误处理与安全

- PostgreSQL 导出、任一必需文件读取或归档生成失败时，整个备份失败，不返回不完整 ZIP，也不更新最近成功时间。
- 缺少 Obsidian 笔记、`.env`、Token、数据库连接或附件目录时，返回明确错误，提示修复对应部署文件后重试。
- 不记录数据库密码、Token、归档内容或用户笔记到日志。
- 备份服务没有宿主机端口，不访问 Docker API；敏感文件只读挂载且只用于归档。
- 专用网络只允许首页后端请求归档服务；PostgreSQL 数据访问仅通过 `backup_db`，首页后端与 Linkwarden 均不加入该网络。
- ZIP 明文包含凭据是用户明确选择的行为；界面、下载前提示和恢复说明均提醒将文件视作密码文件。
- 导入只接受本应用生成且通过清单校验的 ZIP；拒绝绝对路径、`..` 路径、符号链接、重复路径、超出解压限制的文件及不兼容版本，避免路径穿越和解压炸弹。
- 在准备导入时不得修改线上数据。只有回滚备份完整下载且用户二次确认后才进入维护和替换阶段；提交失败时恢复自动保存的当前实例数据。

## 验证

- 后端测试覆盖 SQLite 在线备份、ZIP 清单、pg_dump 成功/失败、必需文件缺失、备份状态迁移及成功确认。
- 前端测试覆盖首次提醒、7 天边界、最近备份时间、下载流完成后提醒消失、下载中断后保留提醒。
- 前端测试覆盖选择文件、校验失败、不允许未下载回滚备份就确认替换、取消导入、成功和失败状态，以及 Linkwarden 顶栏入口。
- 验证 Compose 配置、备份服务网络和挂载没有宿主机端口或 Docker socket。
- 使用隔离的测试数据生成归档，验证 dump 可列出、文件清单完整、敏感文件仅出现在指定归档路径且未写入日志。
- 在隔离数据库和临时目录验证成功导入、数据库切换及中途失败回滚；不覆盖当前 Linkwarden 数据。
- 在本机部署中生成真实归档，并在隔离数据库/文件目录完整导入，确认当前 `.env` 和 Token 未被改动。
- 验证 Linkwarden 入口导航到 `http://localhost:3010`，并可从 Linkwarden 页面返回浏览器首页。
